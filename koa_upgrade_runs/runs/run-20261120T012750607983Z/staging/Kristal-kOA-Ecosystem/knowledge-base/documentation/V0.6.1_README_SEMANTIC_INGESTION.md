# v0.6.1 — Selective README semantic ingestion

This release turns selected repository README claims into first-class Kristal referents instead of leaving them only as evidence files.

## Selection rule

A README detail is promoted when it materially changes one of these axes:

- component purpose or authority boundary;
- reusable capability;
- durable artifact/state object;
- invariant / epistemic rule;
- inter-component or repository relationship;
- evidence and validation semantics.

Operational trivia (install commands, temporary paths, dependency versions, one-off UI labels, styling and branding mechanics) stays in evidence unless it changes an architectural contract.

## Deliberate non-promotions

- THÉOPHILE brand tooling and mini-site remain adjacent/support surfaces; their launch and visual-editing mechanics are not ecosystem capabilities.
- Detailed package versions and Windows launch commands remain evidence, not ontology.
- Individual mathematical challenge contents remain inside challenge repositories; the ecosystem map models their shared authority/state structure instead of copying theorem-level claims.
- README claims remain scoped to their owner repositories. A support dossier does not acquire authority over the systems it describes.

## New first-class referents

v0.6.1 adds:

- 10 capabilities;
- 12 artifacts;
- 7 invariants;
- relations that bind these referents to their owner components or evidence repositories.

The goal is semantic compression: preserve the distinctions that matter for reasoning, validation and composition while avoiding a dump of implementation detail into the ecosystem graph.
