# v0.6.3 — Repository locator canonicalization

This revision moves repository location/link information from presentation-only tables into canonical Kristal source data.

## Canonical fields

Each repository record now carries, when applicable:

- `url` / `public_remote_url`: recorded public remote;
- `public_remote_status`: `recorded` or `not_indexed`;
- `local_path`: observed local repository/project root;
- `local_observation_status`: current, historical/unobserved, or not recorded;
- `repository_locator_status`: public+local, public-only, local-only, or unresolved.

These fields are compiled into the Kristal state as assertions.

## Policy

A missing remote is not guessed from a folder name. A local path proves an observed workspace location, not public availability, architectural membership, runtime activation, or authority. Repository-to-component meaning remains expressed through `koa:realizes_or_supports`.

## Generated views

- `views/repository-map.md` — all repository/project records, remotes, local paths and realized/supported pieces.
- `views/public-repository-directory.md` — only recorded public remotes.
- `views/public-ecosystem-map.md` — system-oriented public navigation surface.
