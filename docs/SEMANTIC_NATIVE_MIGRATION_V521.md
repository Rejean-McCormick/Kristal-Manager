# V5.21 — Candidate native migration (offline)

The exact V5.20 active database 879bcd3e8dea and report are mandatory input. All 127 live workspace state indexes and active profile bytes must match that database. The eight native corpus inputs are additionally pinned to the audited snapshot. Drift, missing evidence, changed source, link/reparse point, conflicting repeated assertion ID, unexpected assertion status, unsupported literal or invalid Framework pin aborts the operation. No network access.

The command generates a private, immutable generation under `%LOCALAPPDATA%\Kristal\SEMANTIC_V521_*` with `report.json`, `active.sqlite`, `manifest.sha256.json`, and `candidates/`. The directory `candidates/<slug>` is a **synthetic validation workspace**, not a Kristal ready to publish. Its synthetic state.index.json and profile exist only to run the pinned Framework/Kit comparison; never copy them into the real workspace. Original V6 bytes, per-occurrence JSON pointers, and exact source SHA-256 accompany the candidate. Native assertion status, applicability, provenance, actionability, notes, source metadata and extensions remain in those originals; V11 triples alone do not encode them. No new assertion truth or external equivalence is certified. Native labels are transcribed, not independently editorially approved. The curated layer review field identifies the deterministic transcription and explicitly denies editorial approval. The crosswalk is empty. IDs are provisional, namespace scoped, deterministic from native refs and occurrence number, and collision-checked. Duplicate native assertion IDs retain separate candidate occurrence IDs; their resolution requires approval. KP absent from the native registry are derived only from explicit predicate positions and not named. Candidate namespaces are proposed, not reserved or active.

The copied V5.20 database contains unchanged active identity, lexical and crosswalk tables. `v521_candidate_identity`, `v521_candidate_lexical` and `v521_native_candidate` are private candidates, never active. `v521_native_pending` lists the remaining 42 workspaces and corpus filenames, not a comprehensive adapter qualification. Only the `MISSING_ACTIVE_LABEL` rows on KA/KS are removed from the copy. The V5.18 generator also filters these in future runs; all-identity coverage counters retain their original meaning. Other review issues are untouched. Re-running with identical inputs verifies the private generation's manifest and reuses it. A crash can leave an uncommitted v521-stage directory; no canonical writes are made.

Next phase requires separate editorial/authority approval of the native-to-V11 adapter, review of duplicate assertions and unstated predicate definitions, namespace reservation, native graph and role preservation checks, registered state transition and recoverable activation, plus independent publication gates. No activation or public writes are implemented in V5.21. The 77 active profiles remain active and 50 remain inactive.
