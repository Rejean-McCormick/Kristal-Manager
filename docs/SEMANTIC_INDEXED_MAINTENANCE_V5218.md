# V5.21.8 — EncyK indexed maintenance

Uses the existing EncyK UNESCO Factory `wikidata_reader_worker.py` and its existing Skope locator and compression index, pinned to the diagnosed code. No full dump scan, no rebuilding, no network. The existing local compression pickle must be trusted by the operator (it is loaded by the existing EncyK reader); never substitute a downloaded/untrusted index. Source authentication is not asserted. Source fingerprint uses paths, size, timestamps, code and small manifest hashes, not a full hash of the 103 GB dump or binary indexes.

Run `scripts/run_indexed_maintenance_v5218.ps1` in kOA. Default batches: 250 QIDs, 600 seconds timeout per worker; same command resumes completed batches (keep same batch size). Cache under `%LOCALAPPDATA%/Kristal/maintenance/indexed_cache_v5218`; incomplete staging directories are not reused. Run only one instance at a time. Output generation `INDEXED_V5218_*` is separate from previous runs; validation ZIP in Downloads. Cached gzip files preserve full returned entity records; final SQLite contains exact lexical projections plus compact fallback observations. If an indexed batch fails, no completed output is emitted; preceding batches remain reusable. Duration depends on random-access cost, not estimated from the three-entity probe.

QIDs use EncyK worker. PIDs and unlocated/rejected QIDs use existing exact-ID compact SQLite query. Compact names are not treated as aliases with a known revision. No guessed `und` language. No historical alias equivalence, accepted crosswalk or canonical mutation. Earlier partial dump and operational dictionary remain unchanged. The standalone diK reader takes `--output <generation> --wid Q42 --lang fr`; this is not integrated into GUI or canonical dictionary. KristalDiag checks cached records, receipts and exact projection; it does not authenticate original dump or re-read it. No automatic publication or editorial approval.
