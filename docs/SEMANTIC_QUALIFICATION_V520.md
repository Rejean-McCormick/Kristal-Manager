# V5.20 — Source qualification and native legacy inventory

Rebuild V5.16/V5.18/V5.19; pin all active roles and  V5.19 source digests. Build a private SQLite qualification database and corrected KQ/KP-only missing-label review view. Native V6 referent lookup uses owner and exact ref only; it does not create a V6→V11 equivalence. Profiles lacking a selected complete V11 group are reviewed individually by native inventory and registered artifact counts; no auto migration.

Default online operation queries the official Wikidata Action API in sequential batches of at most 50 public Q/P IDs, with exact requested locales, no fallback, no redirect and no credentials. It targets accepted anchors on unlabelled KQ/KP and identities with recovered consensus. Raw responses, hashes, retrieval time and requested IDs are retained in the private evidence directory. Candidate review reports agreement/disagreement with exact source terms, out-of-scope languages, absent anchors, unresolved IDs, and unavailable source. Official terms do not independently prove the recorded match. Keep all existing direct labels, including the six historical conflicts. On any transport/API failure, no canonical changes are made for that run; private qualification remains available with an explicit blocker.

If the online phase succeeds, pass only fresh exact-anchored missing direct cells to the Kit. Rebuild federation after successful local updates and emit a final V5.20 active database (with qualification tables), retaining the pre-apply database. If there are no changes, the original qualification DB is also the active DB. The JSON report points to the correct database. `--offline` only runs private inventory; no network or canonical changes. V5.20 is not independent semantic verification, does not resolve candidate mappings or authorize publication. Requires Python 3.10+ with jsonschema and PS7; keep other writers closed.

## V5.20.2 — Resume after rate limiting
The installer and ecosystem entrypoint enable `--resume-latest`. Only a previous completed network-blocked report with no canonical changes is eligible; verify its database digest, response hashes, endpoint, ordered Q/P batches, and retrieval timestamps. Reuse responses up to 24 hours old for the same batch plan, preserving original retrieval times. If the target plan or age differs, query afresh; damaged evidence fails closed. Rebuild the live federation and revalidate local state before applying any canonical changes. New requests are spaced by 15 seconds, with bounded retries for HTTP 429/503 and API maxlag/ratelimited, respecting HTTP Retry-After up to a 600-second wait budget. Longer requests stop rather than retry prematurely. No canonical changes on incomplete acquisition. A subsequent completed network-blocked report preserves the acquired batches for another resume. An abrupt process termination is not a supported checkpoint.
